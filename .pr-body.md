## What

Two additions to the example-set loader (`lib/Service/ExampleSet/`), both in `openspec/changes/example-sets`.

### 1. A kept object follows the objects it references (REQ-EXS-023)

After a partial remove on :8080 (themes deleted, publications kept), the reinstall wrote the themes again with new uuids, but the kept publications still pointed at the deleted ones (`api/themes/<id>` 404 in opencatalogi). `installFragment()` kept an object from the record without looking at its references.

Now, when an object is kept, every top-level field whose declared value holds an `{{object:}}` or `{{lookup:}}` placeholder is resolved again. Only a field that differs from the stored value is written, through `ExampleSetChanges::refresh()`, which reuses `apply()`. The write is recorded as the change `<app>/<key>#references` with the value it replaced (the first old value is kept over later refreshes), so the proof checks it and remove stays exact. An untouched second install writes nothing.

### 2. Per-user preferences (REQ-EXS-024)

A fragment may declare `userPreferences: [{user, key, value}]`, written with `IConfig::setUserValue`:

- only for the fragment's own app (another `app` refuses the set, like `appConfig`);
- only for an account the set creates or adopts (checked against the declared uids in the check and against the record at write time);
- never for a member of `admin`;
- never for a key whose name holds a secret (password, secret, token, credential, private, api key, session) or that Nextcloud's `IUserConfig` keeps as sensitive;
- the old value is recorded. Remove puts it back, or deletes the key, but leaves a value changed after the install and names it. This runs before the set's accounts are deleted.

The consumer is dossiq's tour state (dossiq #3896). A separate dossiq PR adds the staff entries.
