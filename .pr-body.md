## What was wrong

On the local Zuiddrecht demo every public document download on the portal pointed at `http://nextcloud:8080/index.php/s/<token>/download`. `nextcloud` is the Docker service name and no browser can resolve it; the same file answers on `http://localhost:8080`.

`FileService::getCurrentDomain()` and `FileSharingHandler::getCurrentDomain()` took the URL generator's base URL and replaced `localhost` with `trusted_domains[1]`. That came in with 312b59d68 (December 2024, "Use trusted domains when running cronjobs"): from cron there is no request, the base URL reads `http://localhost`, and the second trusted domain was a guess at the public host. It also fired during web requests, it depended on the order of `trusted_domains`, and on an instance that answers on several hosts (cloud.zuiddrecht.nl, zuiddrecht.nl) no single entry is right.

## What changes

- New `OCA\OpenRegister\Service\File\ShareUrlBuilder` builds every absolute file address. During a request it calls `IURLGenerator::getAbsoluteURL()`, which uses the request host and honours `overwritehost`, `overwriteprotocol` and trusted proxies. Without a request (SAPI `cli` or `phpdbg`: cron, occ) it uses `overwrite.cli.url`, and only when that is empty the generator's base. It never reads `trusted_domains`.
- `FileService::getShareLink` and `FileSharingHandler::getShareLink` use it; both `getCurrentDomain()` methods are gone, and with them FileService's only use of `IConfig`.
- `FileMapper::generateShareUrl`, `generateAuthenticatedAccessUrl` and `generateAuthenticatedDownloadUrl` used `getBaseUrl()` directly, which from cron gives `localhost` or the first trusted domain. They use the builder too.
- OpenSpec change `share-links-use-the-request-host`: one requirement in `file-actions`, four scenarios.

## Links already stored

File properties store file ids, and `FileMapper` builds `accessUrl` and `downloadUrl` from the share token on every read, so listed and rendered files are correct as soon as this lands. No migration is needed. Two places keep an absolute link:

- the object `image` column, copied from a file's `downloadUrl` on save (`SaveObject`). `RenderObject` resets it on render when the schema sets `objectImageField`, and a re-save refreshes it. An object saved with the old code under a wrong host keeps that link in the column until then.
- opencatalogi's legacy `FileService::addFileInfoToData` copies the link into attachment data, but `handleFile()` has no caller on opencatalogi `development`.

## Consumers

- portaliq: the site fetches `/attachments` from the browser and uses `downloadUrl` as given, so Open Register sees the visitor's host. No change needed.
- opencatalogi: takes its links from Open Register (`createShareLink`, and `downloadUrl` in DCAT, schema.org, sitemap and PLOOI output), so it is fixed by this PR. Its sitemap, DCAT and PLOOI jobs that run from cron now get `overwrite.cli.url`, which must carry the public address on the platform. No change needed.
