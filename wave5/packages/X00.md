## Why

Task 7.2, decided by Ruben: the published `lib/Contract/ObjectServiceInterface` names eight value types in
`Kernel\Contracts\Value\`, so 16 fleet apps hold 2,911 references to internal Kernel classes only because the
published contract makes them (fleet surface baseline, 19 Nov 2026: `ObjectFindTarget` 955 references in 16 apps,
`ObjectSaveOptions` 912 in 16, `ObjectFindOptions` 764 in 15, `ObjectDeletion` 139 in 16, `ObjectPatch` 42 in 8,
`SaveActor` 38 in 8, `SavePolicy` 35 in 7, `BulkBatchDefaults` 7, `BulkSaveOptions` 7, `LockRequest` 6,
`UnlockRequest` 6 in 3 each; `ObjectValidationVerdict` and `LockRunStep` none). This package makes the published
contract self-contained, so task 7.3 can move the fleet apps onto `OCA\OpenRegister\Contract\` names. It does not
change any fleet app.

## The move

The types: the eight `ObjectServiceInterface` names in its signatures (`ObjectSaveOptions`, `BulkSaveOptions`,
`LockRequest`, `UnlockRequest`, `ObjectFindOptions`, `ObjectDeletion`, `ObjectPatch`, `ObjectValidationVerdict`)
and the five those name in their own signatures (`ObjectFindTarget`, `SaveActor`, `SavePolicy`,
`BulkBatchDefaults`, `LockRunStep`).

For each type `X`:

1. **New `lib/Contract/X.php`** (`namespace OCA\OpenRegister\Contract;`, directly in `lib/Contract/`, not in a
   subdirectory: gate 67 compares only the files directly in `lib/Contract/` with `hydra-gates/contracts/`). The
   class body moves there verbatim: constructor, promoted readonly properties, constants, methods, docblocks.
   Three changes only: the class is no longer `final` (the old name must extend it); a named constructor or wither
   that builds the same class uses `new static(...)` instead of `new self(...)`, so calling it on the old name still
   returns the old type; and type hints on the other promoted types name the `Contract\` class (a widening, since
   the old class extends it).
2. **`lib/Kernel/Contracts/Value/X.php` keeps its name and becomes `final class X extends \OCA\OpenRegister\Contract\X {}`**
   with a `@deprecated` docblock that names the new class. Every `new Kernel\Contracts\Value\X(...)` with positional
   or named arguments, every `instanceof` and every type hint on the old name keeps working: the constructor,
   properties and methods are inherited unchanged. No `class_alias` (BRIEF.md).
3. **`lib/Contract/ObjectServiceInterface.php`** names the `Contract\` classes in its signatures. For parameters
   that is a widening (the old class is a subclass). For the one return type, `validateObject(): ObjectValidationVerdict`,
   the implementation keeps returning the old subclass, which satisfies both names.
4. **The receiving chain inside openregister.** An app that constructs the new name and passes it in must not hit a
   `TypeError` further down. After step 3, change `ObjectService`'s public signatures to the `Contract\` names and
   run phpstan (and psalm) on `lib/`: every call that passes a `Contract\X` into a parameter typed with the old
   `Kernel\...\X` is reported. Widen exactly those parameters (and only those) to `Contract\X`. Construction sites,
   return types and everything else keep the old names; a later package can move them.

What `ObjectFindOptions` and `ObjectFindTarget` name besides values: the Kernel interfaces `RegisterInterface`,
`SchemaInterface` and the Kernel entities `Db\Register`, `Db\Schema`. They stay as they are: the published contract
already reaches them today through these values, promoting `SchemaInterface` (781 lines, 70 methods) is out of
scope, and the decision is flagged in the wave report.
