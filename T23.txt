COLLECTION RULES: one new file per lane, tests/integration/openregister-api-filesettings-anonymisationbackend.postman_collection.json, Postman v2.1, info.description says what it covers and that it seeds its own data. Variables: {{base_url}} (collection default http://localhost:8080), {{admin_user}}, {{admin_password}}; basic auth at collection level; every URL is {{base_url}}/index.php/apps/openregister/api/... A `00 setup` folder creates the register, schema, objects and users the requests need (non-admin users through POST /ocs/v2.php/cloud/users with OCS-APIRequest: true), stores ids in collection variables, and a `99 teardown` folder deletes them; never hardcode an id, slug or user that a fresh instance does not have, and never depend on another collection's data or order. Every request has at least one test that would fail on a wrong answer: the status code AND something about the body (a field value you sent, a count, an error key). For each route cover: the success path; a missing or unknown id (404 or the controller's documented error); invalid input (400/422) where the method validates; and for every route that is not admin-only by design, the access answer for a non-admin user without rights (401/403, or the filtered result) plus an admin or owner who may. An access test asserts the refusal AND that nothing changed (re-read the object). Postman tests may not pin a timestamp, a generated uuid or server timezone output. A route that needs a service CI does not have (an LLM other than the seed stub, Solr, Elasticsearch, a second Nextcloud, an external API): test the documented answer when the service is absent or unconfigured (it must be a clean 4xx/503 with an error message, not a 500); if even that is impossible, put those requests in a second file with `@newman exclude <reason>` in info.description and list them under LEFT (c). A 500 or a PHP error on any input is a finding: list it under LEFT (d) with the request, do not assert it.

TEST RULES (each one has cost us before; a test that cannot fail counts as nothing): (1) A test must fail when the behaviour breaks. For every class or component you cover, prove it on at least one sample by hand: change the production code (flip a condition, return a different value, drop a guard call, skip a write), run your tests, see them go red, revert. Never commit the mutation. Record each sample in the PR body as `mutation: <file>:<line> <what you changed> -> <n> tests failed`. A class where no mutation turns a test red is not covered. (2) No assertion-free or tautological tests: no assertTrue(true), no literal-against-literal, no addToAssertionCount, no expectNotToPerformAssertions or @doesNotPerformAssertions, no assertInstanceOf on an object the test itself built, no assertion that only reads back a stubbed mock return, no method_exists/class_exists checks as the only assertion, no unconditional markTestSkipped. An allow path asserts an observable outcome (the return value, or the exact call and arguments it makes), and is paired with the refusal test that flips the deciding input. Re-run the scanner on your new files before each PR: php /tmp/t1/t1-tools/weak.php . /tmp/t23-weak.json <your test dir>; it must report none of your tests. (3) Goldens and snapshots never depend on the timezone, the clock, the locale or random ids: inject or freeze time (ITimeFactory, a fixed DateTimeImmutable, jest.useFakeTimers with setSystemTime), fix the TZ in the test, and never pin a local time or a generated uuid. A snapshot alone is not a test: every snapshot test also asserts the behaviour it is about. (4) Never weaken a guard and never change production code to make a test pass. This round adds tests; production code belongs to the refactor lanes. If a test shows a real bug, do not pin the bug: leave the test out of the coverage PR, open a separate `fix:` PR with the failing-then-passing test and the smallest fix (only when the file is not in an open PR), no exploit details in the text, and list it under LEFT. (5) Never edit tests/unit/support/* helpers, tests/bootstrap*.php, phpunit*.xml, jest*.config.js or tests/.coverage-baseline.json (the CI lane owns the last three). (6) Prefer new test files. Edit an existing test file only when this brief names it as yours. Other lanes and the refactor lanes (r10b) edit existing tests. (7) PHPUnit calls positional, typed, license header on every new file in the house style (copy the docblock of a neighbouring test: @category Test, @package, @author Conduction Development Team, @copyright 2026 Conduction B.V., @license EUPL-1.2). Mock only what crosses the class boundary (OCP interfaces, mappers, HTTP); never mock the class under test, and never add methods to a mock the real class does not have (no addMethods).
