TEST RULES (each one has cost us before; a test that cannot fail counts as nothing): (1) A test must fail when the behaviour breaks. For every class or component you cover, prove it on at least one sample by hand: change the production code (flip a condition, return a different value, drop a guard call, skip a write), run your tests, see them go red, revert. Never commit the mutation. Record each sample in the PR body as `mutation: <file>:<line> <what you changed> -> <n> tests failed`. A class where no mutation turns a test red is not covered. (2) No assertion-free or tautological tests: no assertTrue(true), no literal-against-literal, no addToAssertionCount, no expectNotToPerformAssertions or @doesNotPerformAssertions, no assertInstanceOf on an object the test itself built, no assertion that only reads back a stubbed mock return, no method_exists/class_exists checks as the only assertion, no unconditional markTestSkipped. An allow path asserts an observable outcome (the return value, or the exact call and arguments it makes), and is paired with the refusal test that flips the deciding input. Re-run the scanner on your new files before each PR: php /tmp/t1/t1-tools/weak.php . /tmp/t36-weak.json <your test dir>; it must report none of your tests. (3) Goldens and snapshots never depend on the timezone, the clock, the locale or random ids: inject or freeze time (ITimeFactory, a fixed DateTimeImmutable, jest.useFakeTimers with setSystemTime), fix the TZ in the test, and never pin a local time or a generated uuid. A snapshot alone is not a test: every snapshot test also asserts the behaviour it is about. (4) Never weaken a guard and never change production code to make a test pass. This round adds tests; production code belongs to the refactor lanes.
