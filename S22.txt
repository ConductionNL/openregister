In short: Rule 1, shared value objects: `Register $register, Schema $schema` becomes `RegisterSchema $table` (OCA\OpenRegister\Db\RegisterSchema); `string $register, string $schema, string $id` becomes `ObjectRef $ref` (OCA\OpenRegister\Kernel\Contracts\ObjectRef; the id-less pair is RegisterSchemaRef); limit/offset/filters/sort/search become `ListQuery $query` (OCA\OpenRegister\Db\ListQuery); nothing else in that method changes. Rule 2, component-local objects: any other recurring cluster is a final value object with public readonly fields beside the class that uses it; a public method with 4 or more parameters, or 3 parameters and a body of 12 lines or more, takes one operation object named after the operation (ExportRequest, MergeInstruction, TransitionCommand), never after the method or class, and it may have one user; mostly-optional parameters become the required ones plus one typed `<Operation>Options` class with named fields and defaults. Rule 3, run objects: when 3 or more private helpers share the same 2 or more parameters, the entry point builds an `<Operation>Run` (model: CascadeRun in lib/Service/Object/SaveObject.php) and the helpers take the run plus at most one more parameter; a run never leaves the class that built it. Rule 4, constructors: a controller takes `(IRequest $request, <Name>ControllerServices $services)`, the app id from Application::APP_ID and ControllerSession inside the bundle (pattern lib/Controller/Support/*ControllerServices.php); an autowired class takes at most 2 constructor parameters through named aggregates (final, public readonly members, at most 4 members, at least 3 consuming classes, named after the capability, never after one consumer, at most one level deep); SchemaCatalog (register, schema and magic mappers, from Q01) is the first; a constructor that only stores its parameters uses promoted properties and an empty body; value objects and events keep their fields as constructor parameters.
