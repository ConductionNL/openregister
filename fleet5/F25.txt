It is written for openregister; in an app it applies like this: Rule 1's shared value objects (RegisterSchema, ObjectRef, ListQuery) are openregister classes: use them only where the app already receives them, never copy them into the app. Rule 2 component-local objects: a recurring cluster becomes a final value object with public readonly fields beside the class that uses it, in the app's own namespace; a public method with 4 or more parameters, or 3 parameters and a body of 12 lines or more, takes one operation object named after the operation (ExportRequest, MergeInstruction, TransitionCommand), never after the method or class; mostly-optional parameters become the required ones plus one typed `<Operation>Options` class. Rule 3 run object: when 3 or more private helpers share the same 2 or more values, the entry point builds an `<Operation>Run` and the helpers take the run plus at most one more parameter; a run never leaves the class that built it. Constructors are not changed in this wave. Rule 5: public methods that other Conduction apps or a route call keep their signature (add the value-object method beside it and make the old one build the object and delegate in at most 5 lines; route actions keep their route parameters). No option arrays, no variadics, no generic Context bag, no value object that mirrors one method's parameter list under a generic name (FooArgs, BarParams), no moving values to a mutable field on a shared service. New units also stay at cyclomatic complexity 5 or below. Keep every moved body in a file with the same declare(strict_types) mode as its source. No migrations, stored data, register or schema JSON, manifest, routes, occ commands, l10n or info.xml changes. Guard flags such as `_rbac` and `_multitenancy` stay named parameters wherever they appear. Add no new @SuppressWarnings or eslint-disable; leave an existing one in place when moving code unless the warning is really gone. Typed props assigned one by one, no list destructuring into props, PHPUnit calls positional, license headers on new files (copy the header of a neighbouring file in the same directory, including its licence).
PROCEDURES ARE CONFIGURATION: helpers and collaborators are named after what they do (formatAddress, resolveDeadline), never after a procedure, client or case type.
CALLERS: splitting a method into private helpers changes no public signature, so prefer that. Change, move or remove a public method only when every in-repo caller sits in a file you own: migrate them all in the same PR and list every caller in other Conduction apps in the PR body under 'Fleet callers' (app, file:line, method); find them with `gh api -X GET search/code -f q='org:ConductionNL <method>'`. A public method with a caller in a file you do not own keeps its signature: list it in LEFT. No compat delegates beyond the ADR-011 Rule 5 delegate. String lookups (Server::get, method_exists, [$obj,'method'], container ids, Vue component names in a manifest) and named arguments count as callers.
