In the browser the same calls take 600-800 ms because requests of one session are served one at a time: 8 parallel fetches of one endpoint from a logged-in browser finish in a staircase (46, 79, 114 ... 346 ms; sequential 40 ms each), and core endpoints do the same with launchpad and OpenRegister disabled (user_status: 22-175 ms staircase), so it is the PHP session lock of the stack. Levers, in order: (1) fewer calls at load: setup/status is fetched twice per load and the walkthrough preference twice (value + -progress); carry both in the workspace initial state like dashboardFirstLoad/workspaceBootReads; (2) release the session early in read-only API controllers; (3) Redis as session handler on the reference stack (ops, not app). Basic-auth requests cost ~550 ms each (password hash per request): measure with a session or an app token, never with Basic auth.
