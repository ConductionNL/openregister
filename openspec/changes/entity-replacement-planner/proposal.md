## Why

Anonymisation currently decides *what* to replace and *how* to apply it in the same breath: `DocumentProcessingHandler::anonymizeDocument` builds a `needle => placeholder` map (`lib/Service/File/DocumentProcessingHandler.php:425-472`), orders it longest-first (`uksort`, `:489-495`), and then hands that map to a per-format branch that walks it with `str_ireplace` — the sanitised-office-container branch (`:918`), the docx branch (`:1033`), and the plain-text branch (`:1216`). The PDF branch instead delegates matching to SAPP (`lib/Service/File/Pdf/PdfTextReplacer.php:212`), which re-asserts the same ordering defensively (`:177-184`).

The longest-first ordering is correct and was added deliberately — it fixes cross-entity **containment**, the case where a bare `Amsterdam` [LOCATION] rewrites `gemeente Amsterdam` before the longer needle can match, and equally the case where a PERSON needle `rjzondervan` turns `robert@rjzondervan.nl` into `robert@[PERSOON: 1].nl`, leaving a local part and a domain that are themselves identifying. That guarantee is not the problem. The problem is that sequential `str_ireplace` over an ordered map is the wrong primitive for the remaining failure modes, and four of them are live today:

1. **Text the matcher cannot see.** The docx branch replaces per PhpWord element (`$element->getText()` / `setText()`, `:1030-1037`), so an entity split across two `<w:r>` runs — which Word produces routinely at formatting, spell-check and `rsid` boundaries — is never matched and stays in the output verbatim. This is already known and documented in-tree as a deliberate parity concession, not a fixed bug: *"`str_ireplace` cannot reach text split across `<w:r>` runs"* (`lib/Service/File/Pdf/PdfTextReplacer.php:288-292`). Ordering cannot reach it, because the needle never appears contiguously in any single string the loop is given.

2. **Overlap is not containment.** `Jan de Vries` and `Vries-Bakker` in `Jan de Vries-Bakker`: neither contains the other, they compete for the shared `Vries`. Longest-first cannot express competition — it replaces one, the other silently never matches, and `Bakker` survives. Hyphenated surnames make this an ordinary Dutch case, not a contrived one.

3. **No word boundaries.** `str_ireplace` is a raw substring replace, so a PERSON needle `Jan` also rewrites `Janssen` and `Bas` rewrites `Bassin`. Over-redaction destroys document utility, and — because the check that would notice runs only on PDF — nothing reports it.

4. **Three of the four paths never report what they missed.** The canonical residual contract already exists (`openspec/specs/pdf-anonymisation/spec.md:165-188`): re-extract the output, collect surviving substitution-map keys, produce the file anyway, and surface `{success: true, complete: false, residual_count, residual_entities}` so the operator can iterate. It is implemented **only** for PDF (`PdfTextReplacer::validateOutput`, `:320`, feeding `lastResidualEntities` at `DocumentProcessingHandler:1379-1394`). For docx, odt and txt `getLastResidualEntities()` returns `[]` unconditionally — indistinguishable from "fully anonymised". A partially-anonymised docx is therefore reported to the operator as complete.

There is also a matching-semantics mismatch worth closing while we are here: the apply step is case-**insensitive** (`str_ireplace`), while the PDF residual check is case-**sensitive** (`mb_strpos` on `$normalisedNeedle`, `PdfTextReplacer.php:411-418`). A residual whose case differs from the stored needle is therefore not reported even on the one path that reports at all.

Finally, none of the matching semantics for docx/odt/txt are specified anywhere. The `@spec` annotations on those methods point at `office-document-sanitization` (which governs stripping comments, tracked changes and metadata — a different concern) and at `file-actions` / `tag-preserving-redaction` on the entry point. The longest-first guarantee that all three depend on lives in a code comment and a defensive re-sort, with no requirement behind it and no test that would fail if someone removed it.

## What Changes

- **A format-agnostic replacement planner.** A new service separates the decision from the application: given the immutable original text and the substitution map, it produces a **plan** — a set of non-overlapping accepted ranges plus the list of needles that matched nothing — and never mutates text while deciding.
- **Maximum-coverage claiming, not longest-first.** Candidate matches are selected to maximise the number of redacted characters via weighted-interval-scheduling DP, with deterministic tie-breaks. This subsumes longest-first (a contained needle always loses to its container, so `robert@rjzondervan.nl` beats `rjzondervan`) and additionally resolves the partial-overlap case that longest-first cannot express.
- **Residue coverage.** When a candidate is rejected because it overlaps an accepted range, the part of it that is still uncovered is redacted too. `Jan de Vries-Bakker` becomes `[PERSOON: 1][PERSOON: 2]` rather than `[PERSOON: 1]-Bakker`. Leaving identifying text behind is worse than an adjacent placeholder pair, and the existing duplicate-collapse helper (`PdfTextReplacer::collapseAdjacentDuplicatePlaceholders`, `:477`) already handles the cosmetics.
- **Single-pass application.** The output is **built** — slice, placeholder, slice — never progressively mutated. An inserted placeholder can therefore never be rescanned by a later needle, which is a hazard longest-first actively worsens by running the shortest needles last.
- **Per-type boundary policy.** Free-text types (`PERSON`, `ORGANIZATION`, `LOCATION`) require Unicode-aware word boundaries; structured identifiers (`EMAIL`, `IBAN`, `BSN`, `PHONE`, `IP_ADDRESS`, postcode) match literally, because their extent is unambiguous and they legitimately abut punctuation.
- **flatten → plan → scatter for segmented formats.** A per-format adapter exposes the document as an ordered list of text segments; the planner runs on their concatenation; the writer maps accepted ranges back, splitting across segment boundaries. This is what makes the docx cross-run case (failure mode 1) matchable at all — the placeholder lands in the segment holding the range's start, and the covered part of every subsequent overlapped segment is removed.
- **The residual contract becomes format-agnostic.** `getLastResidualEntities()` is populated on every path, from the planner's unmatched-needle list plus a post-apply verification using the *same* matching semantics as the apply step (same case folding, same boundary policy). PDF's existing `validateOutput` result is reconciled into the same shape.
- **PDF keeps SAPP as its matcher.** Content-stream offsets are not usefully addressable from extracted text, and SAPP already owns the cross-operator / cross-block / cross-line passes. The planner contributes the ordered needle set, the boundary flags and the unified report — not a replacement for `replace_text_in_document`.
- **The ordering guarantee gets a spec and tests.** The behaviour currently defended only by a comment and a defensive `uksort` becomes a stated requirement with scenarios, so removing it fails a test rather than silently regressing redaction.
- **NOT breaking for any API surface.** No route, request or response shape changes; the placeholder format `[<TYPE>: <id>]` is untouched. Output bytes *do* change for documents that were previously partially anonymised — because more text is now correctly redacted, and because rejected-candidate residue is now covered.

## Capabilities

### New Capabilities
- `entity-replacement-planner`: the shared match → claim → apply → report contract for entity replacement across every file format. Owns candidate enumeration on the immutable original text, maximum-coverage range selection with deterministic tie-breaks, residue coverage, per-type boundary policy, case-folding semantics, single-pass application, the segment (flatten → plan → scatter) abstraction for formats that do not hold text as one string, and the unmatched-needle report that feeds `getLastResidualEntities()`. This capability is new because no existing spec governs matching semantics for the docx, odt or plain-text paths — the longest-first guarantee they rely on is currently unspecified.

### Modified Capabilities
- `pdf-anonymisation`, on three requirements:
  - **Residual reporting** (`spec.md:165-188`) is generalised from a PDF-specific validation pass to one implementation of the format-agnostic report owned by `entity-replacement-planner`. The best-effort (not fail-closed) policy, the `{success, complete, residual_count, residual_entities}` response shape, the PII-free-logs rule and the strict-mode fail-closed behaviour are all retained unchanged; what changes is that PDF is no longer the only path required to produce it, and that the residual check MUST use the same case-folding and boundary semantics as the apply step rather than the current case-sensitive comparison. SAPP's rejected-substitution stat must also be reconciled into the same list.
  - **Placeholder emission** (`spec.md:59-74`) gains a clarification that the planner never authors placeholder text either, and that residue coverage can legitimately emit two adjacent placeholders for what a reader perceives as one name.
  - **"NO breaking changes for DOCX / ODT / text branches"** (`spec.md:203-218`) is **re-scoped**, and this is the one place where the change contradicts an existing requirement rather than extending it. That requirement was written as a scope fence for the PDF work — reasonable then, since `pdf-anonymisation` targeted the PDF branch exclusively — but its literal wording requires DOCX/ODT/text output to stay byte- or semantically identical across changes. This change deliberately changes that output, because that is where the three defects live. The re-scoping keeps the parts that are genuinely still binding (the `anonymizeDocument` public contract, the MIME dispatch structure, and the fence itself for any future PDF-scoped change) and supersedes only the output-identity clause. Called out explicitly rather than quietly overridden, because a spec conflict discovered at archive time is worse than one negotiated up front.
  - A new requirement is **added** to the same capability recording that PDF replacement stays delegated to SAPP, so the planner is not later mistaken for a replacement of `replace_text_in_document` and the defensive `uksort` is not deleted as redundant.

## Impact

- **New service:** `lib/Service/File/Anonymisation/ReplacementPlanner.php` plus value objects (`ReplacementPlan`, `ReplacementRange`, `SegmentMap`) and a `BoundaryPolicy` resolver keyed on the canonical `EntityRecognitionHandler::ENTITY_TYPE_*` constants. Pure, no Nextcloud dependencies, no I/O — directly unit-testable, which the current inline `str_ireplace` loops are not.
- **`DocumentProcessingHandler::anonymizeDocument` (`:365`):** the map build (`:425-472`) is unchanged; the `uksort` (`:489-495`) moves into the planner as part of candidate ordering and is no longer the mechanism that provides the overlap guarantee. Per ADR-011 the existing comparator is reused, not re-derived, and its untyped-closure caveat (PHP coerces purely-numeric needles such as a spaceless BSN to `int` array keys, `:485-488`) carries over to every place needles are compared or used as keys.
- **Three apply sites replaced:** the sanitised-office-container `str_ireplace` (`:918`), the docx per-element closure (`:1027-1060`), and the plain-text `str_ireplace` (`:1216`) each become "build segments → plan → scatter". The docx adapter is the substantive one and the only place new correctness risk is introduced (see design Risks).
- **PDF path (`:1285`):** `PdfTextReplacer::replaceInPdf` keeps its defensive re-sort and its SAPP delegation. Its `validateOutput` (`:320`) gains the shared case-folding/boundary semantics, and its residual list is reconciled with SAPP's `rejected_substitutions` stat (`:276`) into the common report.
- **Report surface:** `getLastResidualEntities()` (`:211`) and the `{text, type, id}` record shape built at `:1379-1394` are unchanged as a contract; only their coverage widens from PDF to all formats. The type/id are recovered from the placeholder via the existing regex (`:1385`), which is type-agnostic and so unaffected by localized labels.
- **EML:** the `text-extraction-eml` change (active, `openspec/changes/text-extraction-eml/`) adds EML handling; its redaction path MUST consume the planner rather than growing a fifth `str_ireplace` loop. Flagged as a sequencing dependency, not a code dependency — whichever lands second adopts the planner.
- **Cross-app (DocuDesk):** DocuDesk's grondslagen-summary already consumes `residual_entities`; widening coverage means docx/odt/txt anonymisations can now legitimately return `complete: false` where they previously always returned complete. This is a truthfulness fix, but DocuDesk's UI must not treat a non-empty residual list on a non-PDF file as an error state. Cross-app follow-up.
- **Performance:** candidate enumeration is O(needles × text length) with `mb_strpos` scanning, and the DP is O(candidates log candidates). At document scale (tens of needles, hundreds of KB) this is comfortably cheaper than the current `count($replacements)` full-string `str_ireplace` passes, each of which already rescans the entire document.
- **No new schemas, objects, tables or migrations.** Nothing is persisted; the plan is per-run in-memory state.
- **Project-branch port:** this lands on `development` first, then ports to `test/anonimiseren-bij-de-bron-or`. `DocumentProcessingHandler` diverges heavily between the two — the project branch still has the pre-refactor shape with a separate `buildEntityReplacements()`, per-format ODF range computation (`computeOdfReplacementRanges`, `rebuildOdfSegmentValues`, `extractOdfConcatenatedText`) and an EML `redactText()` path, and it has no `uksort` at all. The port is therefore a **semantic port, not a cherry-pick** — the same caveat recorded for `anonymisation-placeholder-id-scope` (`proposal.md:40`). The project branch's ODF range code is the closest existing analogue of the planner and should be deleted in favour of it during the port, not kept alongside.
