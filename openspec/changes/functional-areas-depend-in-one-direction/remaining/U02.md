# U02: references kept (Core to Files, `lib/Service/File`)

Wave 4 package U02 started from 12 references against the order in eight `lib/Service/File` files
(main `3ec81519`). Eleven are removed by counting the file store to Files (contract design
`contracts/files.md`, A1). One is kept.

| Source file | Target file | Why no allowed move fits | What lets it go later |
|---|---|---|---|
| `lib/Service/File/FolderManagementHandler.php` (Core) | `lib/Service/FileHandlerSupportInterface.php` (Files) | The handler is file-storage work, so its row belongs with the rest of the file store in Files. Counting it to Files now adds 5 references against the order: `SaveObject` (`assertFolderIsAccessible`), `Rbac/ObjectShareReader` and `Rbac/ObjectShareSurface` (`getObjectFolder`, `getNodeById`), `BackgroundJob/SharerAccessSweepJob` (`getOpenRegisterUserFolder()->getOwner()`) and `ServiceRegistrar` (its factory). The handler only calls `getUser()` on the facade, which the Core port `FileAccountInterface` already answers, but `FileService` hands itself to the handler through `setFileService(FileHandlerSupportInterface)` (its `HANDLERS_NEEDING_SERVICE` list), so the parameter cannot narrow to the port without changing `FileService`, which is package U03's file. A Core port that copies the facade would be the forbidden copy. | Either (a) the design's B3a/B3b: the Core port `FolderBindingCheckInterface` (C1) for `SaveObject`, `getNodeById` on `ObjectFolderLookupInterface` (C2) for the two Rbac classes, `FileAccountInterface::getUser()` for the sweep after a golden test shows the same UID, and the factory moved from `ServiceRegistrar` (package U04) to `FilesRegistrar`; then the row moves to Files with its helpers `FolderAccessDenial`, `FolderBindRun`, `ManagedFileOwnerLookup` and `ObjectFolderOptions`. Or (b) `FileService` stops handing itself to the handler and the handler resolves `FileAccountInterface` itself; then the reference goes while the handler stays in Core. |

Wiring left as it is: `ContractBindings` (Configuration) still aliases the file-store contracts
(`FileServiceInterface`, `FileHandlerSupportInterface`, `FileReaderInterface`, ...) to `FileService`.
After this change that is Configuration binding a Files class, which points down and adds nothing
against the order; moving those aliases into Files' own map is the design's B6 wiring step.
