# U04: references kept in `Service/ServiceRegistrar.php`

Package U04 (wave 4) moved seven of the eight references of `lib/Service/ServiceRegistrar.php` (Core) against the order to the registrar of the area that owns the class (allowed way 5, wiring):

- Integrations: `CredentialStore`, `CredentialStoreResolver`, `EmailLinkService`, `Sync/SourceFetcherRegistry` and `Sync/RestApiSourceFetcher` now go through `IntegrationWiring`.
- Configuration: `Translation/TranslationProviderInterface` and `Translation/TranslationProviderResolver` now go through `ConfigurationServiceRegistrar`.

One reference is kept.

| Source | Target | Why no allowed move fits now | What lets it go |
|---|---|---|---|
| `lib/Service/ServiceRegistrar.php` (Core) | `lib/Service/LanguageService.php` (Configuration) | `LanguageService` is the request-language negotiation, which Core reads on every object read (`MagicMapper`, `TranslationHandler`, `RenderTranslations`, `PropertyTitles`, `AggregationRunner`). The merged Configuration contract design (`contracts/configuration.md`, item A1) puts it in Core. Moving its shared-instance factory into `ConfigurationServiceRegistrar` would remove this one reference only to bind a class that A1 counts to Core from the Configuration registrar, which breaks "a registrar binds only its own area's classes" once A1 lands. A port is not needed: Core already owns the work. | The open PR #10929 (package V03, A1) re-rows `LanguageService` to Core. When it merges, this reference is Core to Core and disappears without touching `ServiceRegistrar`. |
