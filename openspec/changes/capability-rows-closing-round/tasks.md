## 2. A register as one unit

- [x] 2.1 Pin the round trip: export a register with two schemas and its records, import it on an empty instance, and compare. Verify: a Newman or PHPUnit test against `registers#export` and `registers#import`.
  - 2026-11-25, measured on a sandbox Nextcloud 34 on MariaDB, and it does NOT round-trip, so nothing is pinned yet: `GET /api/registers/{id}/export?format=configuration&includeObjects=true` of a register with two schemas and three records exports both schemas and the three objects; after deleting them, `POST /api/registers/{id}/import` with that file is routed to the register-bundle importer (a `.json` with `components.registers`), which refuses it with 400 'Register bundle import requires exactly one schema when no schema is explicitly specified; found 2' AFTER creating the register and both schemas (they are left behind, empty); with `type=configuration` the same file answers 404 for a missing register, and into an existing register 400 'importFromJson must be called with a Configuration entity'. The bundle importer is single-schema by design (register-import-auto-create); a two-schema round trip needs that importer to route each object by its `@self.schema`, which is that change's call.
  - 2026-11-26: built. A bundle of several schemas no longer stops at 'requires exactly one schema'. Each record is saved into the schema its `@self.schema` names (`lib/Service/Import/BundleObjectRouting.php`, called from `ImportService::runBundleImportJob()`), and the summary is keyed by schema slug. A record that names no schema of the bundle is reported under `unassigned` and saved nowhere. The import also had a second defect the first could not show: the auto-created register was given the export's schema SLUGS as its `schemas`, so even a one-schema bundle came back with a register that could not find its schema. It now links the ids of the schemas the import created. Pinned by `tests/Api/RegisterRoundTripTest.php`: export a register with two schemas and three records, delete them all, import the file, and read back both schemas linked and every record in its own schema. It ran green on a sandbox Nextcloud 34 on MariaDB and on PostgreSQL 16, and red on main's importer with the 400 above. Unit tests: `BundleObjectRoutingTest` (6) and `ImportServiceRegisterAutoCreateTest` (+2). The `import-from-json-golden.json` fixture was re-recorded for the register's schema ids and the two-schema case.
