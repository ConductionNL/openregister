# Tasks: Register Resolver Service

## Phase 1 — Core service

- [x] 1.1 Add `lib/Service/RegisterResolverService.php` with the five public methods (`resolveRegisterId`, `resolveSchemaId`, `resolveRegister`, `resolveSchema`, `resolvePair`). Wire it into `lib/AppInfo/Application.php` as a public DI-resolvable service. **Implementation note: NC's auto-wiring container resolves the constructor (IAppConfig + RegisterMapper + SchemaMapper + OrganisationService + LoggerInterface) — all five dependencies are explicitly registered upstream — so the service does not need its own factory closure. Documented in Application.php's class PHPDoc under "Public services exposed for consumer apps".**
- [x] 1.2 Add `lib/Service/Resolver/RegisterSchemaPair.php` — readonly value object holding `Register` + `Schema` + the two slug/ID strings (single getter per field, no setters).
- [x] 1.3 Add the three exception classes under `lib/Service/Resolver/Exception/`: `MissingConfigException` (with `getAppId()` + `getConfigKey()`), `RegisterNotFoundException` (with `getAppId()` + `getConfigKey()` + `getResolvedValue()`), `SchemaNotFoundException` (same accessors as `RegisterNotFoundException`). **Implementation note: the existing `OCA\OpenRegister\Exception\RegisterNotFoundException` / `SchemaNotFoundException` use a single-arg constructor (`new ...($slugOrId)`) and a different code path; placing the resolver exceptions in their own namespace (`OCA\OpenRegister\Service\Resolver\Exception`) avoids the name collision and lets callers `catch` the resolver-specific shape unambiguously. Both layers extend `\Exception`; no shared `OpenRegisterException` base class exists in `lib/` yet, so we extend `\Exception` directly and rely on the namespace to keep them distinct.**
- [x] 1.4 Implement request-scoped caching: `array<string,Register>` keyed by `"{appId}:{configKey}:{organisationUuid|''}"` after the first lookup; same for schemas. Cache MUST clear if `MultiTenancyTrait` reports a tenant switch within the same request (rare; defensive). **Implementation note: tenant-switch detection goes through `OrganisationService::getActiveOrganisation()` (the public surface MultiTenancyTrait reads from internally); each resolve call records the active UUID and flushes both caches when the UUID changes between calls.**

## Phase 2 — Tenant awareness

- [x] 2.1 Resolve entities through `RegisterMapper` / `SchemaMapper` via existing `findBy*` methods that already apply `applyOrganisationFilter`, so the active organisation context is respected. Add an optional second parameter `?string $organisationUuid = null` to all four resolve methods; when provided, scope the lookup to that organisation explicitly (used by cross-tenant admin tooling). **Implementation note: when `$organisationUuid` is null, we let the mapper's standard `applyOrganisationFilter` handle scoping; when explicit, we bypass multi-tenancy at the mapper layer (`_multitenancy: false`) and verify membership against the entity's `getOrganisation()` after fetch — so an explicit override either matches the entity's org or surfaces a `RegisterNotFoundException` / `SchemaNotFoundException`.**
- [x] 2.2 When the resolved Register exists but is NOT visible in the caller's organisation, throw `RegisterNotFoundException` (NOT `MissingConfigException`) — the config IS set, the entity IS missing in the caller's tenant. Distinct error path matters for admin diagnostics.
