## 3. EmlParser service

- [x] 3.1 Create `lib/Service/TextExtraction/EmlParser.php` with constructor taking the logger and (lazily) `TextExtractionService` (avoid circular DI — inject via the container with a method). Implement `parse(File $file): EmlStructure` using `\ZBateson\MailMimeParser\MailMimeParser`: extract From/To/Cc/Subject/Date/Message-ID; decode RFC 2047 encoded-words via the parser's built-in handling; Date parsing tries `DateTimeImmutable::createFromFormat` with RFC 2822/5322 patterns, falling back to null.
- [x] 3.2 Implement body extraction (get `text/plain` and `text/html` parts independently; populate `EmlBody` with both/null per part) and attachment extraction via `getAllAttachmentParts()`. For each attachment: filename resolution order is Content-Disposition `filename` → Content-Type `name` → generated `attachment-<1-indexed-position>` (generated form MUST always be non-empty); mimeType; content MUST be the **decoded** bytes via `$part->getContent()` (NOT `getRawContent()`) so consumers can embed them as PDF/A-3 file attachments or `data:` URIs without further decoding; isInline (Content-Disposition: inline); contentId (Content-ID header, stripping angle brackets).
- [x] 3.3 Implement recursive `nestedEml` for `message/rfc822` attachments with depth parameter (default 0, recursive call increments depth). At depth 3, set `nestedEml: null` and emit a debug log "EML nesting depth limit reached". Encoding fallback: when `mb_check_encoding($value, 'UTF-8')` is false, run `mb_detect_encoding` then `mb_convert_encoding` to UTF-8.
- [x] 3.4 Implement `flatten(EmlStructure $structure, int $depth = 0): string` per spec D2: header block, blank line, body (plainText preferred; HTML stripped to text fallback), attachments. For extractable attachments (PDF / Word / text / nested EML) call `TextExtractionService` to get attachment text and inline it; for non-extractable, emit marker line only. Multipart/alternative preference is explicit: when a body has both `text/plain` and `text/html` in a `multipart/alternative`, `flatten()` MUST use the plain text and MUST NOT concatenate the HTML. **v1 scope:** non-EML extractable attachments (PDF/Word/text inside an EML) are listed by filename + MIME marker only — inline text extraction requires a `TextExtractionService::extractFromBytes` primitive that does not yet exist (cycle-free DI). Nested EML inlining via recursive `flatten()` is implemented. DocuDesk's `eml-pdf-assembly` handles rich attachment rendering separately and does not depend on flat-path inlining. Tracked as a follow-up under the EML-text-extraction documentation page.
- [x] 3.5 Implement HTML→text helper for the flat-path body fallback: drop `<style>` and `<script>` content (block-level removal); convert `<br>`, `<p>`, block-level tags to newlines; strip remaining tags via `strip_tags()`; decode entities via `html_entity_decode()`; collapse whitespace runs.
- [x] 3.6 `parse()` MUST throw `EmlParseException` on irrecoverable error (NOT return null, NOT a partially-populated structure); `flatten()` does not throw (works on a successfully-parsed structure). Sanitise log lines + exception messages per ADR-005 in BOTH `EmlParser::parse`'s sanitised re-throw AND `extractEml`'s catch: replace email addresses, display names, Subject content, body content, and attachment filenames with `<redacted>`; permitted log payload is file ID, MIME type, exception class name, structural detail (depth-limit hit, etc.).
