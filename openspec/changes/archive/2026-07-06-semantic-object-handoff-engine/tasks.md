## 2. HandoffService

- [x] 2.1 Add `lib/Service/Handoff/HandoffService`: load source via `ObjectService` under the caller's RBAC; read the declared entry (`handoff-not-declared` when absent); resolve the provider via `SemanticTypeResolver::resolveSchemaByImplements` filtered to schemas with a complete `handoffContract` binding.
- [x] 2.2 Add the mapping evaluator: `from` copy (+ optional `default`), `const`, `template` (`{{prop}}` interpolation, HTML-escaped, existing convention), `semanticRef` (carry the reference UUID — never dereference or copy referenced data), `provenance` (engine-filled source pointer); translate contract fields to provider properties exclusively through the `handoffContract` binding. → `lib/Service/Handoff/HandoffMappingEvaluator.php`
- [x] 2.3 Make steps create→relations→audit→`onSuccess.set` all-or-nothing: target create through the `ObjectService` write path, `handoff` typed relation on both objects (`handoff:<id>:handed-off-to` / `handoff:<id>:originated-from`), one immutable audit row per side (actor, kind, handoff id, correlationId, resolved schema, deferred flag) via `AuditTrailMapper`, source update through the lifecycle-aware write path; any failure surfaces the underlying error and leaves no partial state.
  — DEVIATION (verified live on postgres): a single wrapping `IDBConnection` transaction is infeasible — `ObjectService::saveObject` issues swallowed best-effort probe queries (MySQL-only `SHOW VARIABLES`, cross-schema magic-table COUNTs) and postgres aborts a caller-managed transaction on ANY failed statement (SQLSTATE 25P02). Implemented as: target create (atomic in OR's own path) → `onSuccess.set` (compensated by target delete on failure) → relations+audit in one real DB transaction (rollback + compensation: target delete + source restore). Observable contract preserved: a failed handoff leaves no target, no relation, no handoff audit row, no source mutation. See design.md "Atomicity — implementation note". The MySQL-ism itself is fixed platform-guarded in `MagicMapper`/`MagicBulkHandler` as part of this change.
- [x] 2.4 Enforce RBAC without escalation: write on the source AND create on the resolved target schema, both as the calling user; permission denial → typed 403 before any write.
- [x] 2.5 Support `trigger: lifecycle:<state>` by invoking the same `execute()` from a lifecycle-transition listener with the transitioning user as actor. → `lib/Listener/HandoffLifecycleListener.php` (system transitions with null user are gated out — no system-user privilege lane).
