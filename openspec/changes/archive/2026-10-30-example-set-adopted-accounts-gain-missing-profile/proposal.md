# An adopted account gains the profile fields it lacks

## Why
DqAfdelingen draws each staff member's function under their name. Pieter Jansen's cast entry declares "Woo-coördinator", but his account is adopted (it existed before the set), and the set left an adopted account's profile alone. His headline stayed empty. A one-time write on :8080 would not hold: nothing in the set would give it back after the next install.

## What changes
- An account the set adopted gains the function (headline) and role that the cast declares and that the account has empty.
- A value the account holds is never overwritten.
- Absence and status are a person's own day, not missing fields, so an adopted account keeps them as they are.
- An account the set created gets its whole profile at every install, as before.
