## Phase 1 — Canonical event-driven-architecture amendments

- [x] 1.1 Verified the canonical `openspec/specs/event-driven-architecture/spec.md` against the amendment surface. The canonical had a partial scenario for `ObjectTransitionedEvent` (line 402 — "State-machine transitions MUST dispatch a typed ObjectTransitionedEvent") + a passing mention of `x-openregister-lifecycle` in that scenario's context — but NO annotation contract, NO uniqueness constraint, NO pre-save validator listener requirement, NO initial-state listener, NO sugar transition endpoint, NO `LifecycleGuardInterface`, NO `available-actions` endpoint, NO deterministic `(from, to)` action resolver. All 7 amendments below land non-duplicating against the existing surface.
- [x] 1.2 Applied the `## ADDED Requirements` block — see `specs/event-driven-architecture/spec.md` in this change directory (already shipped per the openspec workflow's delta convention).
- [x] 1.3 Merged the 7 ADDED Requirements into `openspec/specs/event-driven-architecture/spec.md` between the last existing requirement ("Object unlock MUST dispatch a typed ObjectUnlockedEvent") and the "Current Implementation Status" section. Requirements added (each with at least one scenario): (1) Schemas MAY declare a state machine via `x-openregister-lifecycle` + uniqueness constraint, (2) pre-save validator rejects invalid transitions via `setErrors()`, (3) initial state forced on creation, (4) sugar `POST /api/objects/{id}/transition` endpoint with the full `#[NoAdminRequired]` / non-`#[NoCSRFRequired]` auth contract, (5) `LifecycleGuardInterface` registration, (6) deterministic action resolution for direct PATCH via the `(from, to)` lookup, (7) `GET /api/objects/{id}/available-actions` endpoint.
