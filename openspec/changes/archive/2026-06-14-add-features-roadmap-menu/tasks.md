# Tasks: add-features-roadmap-menu

Depends on `add-github-issue-proxy` (paired OR backend) being applied first.

> **Handoff scope.** Section 1 lives in `@conduction/nextcloud-vue` (component family,
> composables, utils — published from that repo). Sections 2 and 3 — originally
> scoped as two new npm packages (`@conduction/openspec-manifest`,
> `@conduction/docusaurus-features`) — have been **rescoped to live in-repo**
> per the W33 honest-handoffs review (2026-06-12). The local builder
> `scripts/build-features-manifest.js` is the canonical extractor; the
> Docusaurus surface is a per-site `src/pages/features.js` template (~30 LOC)
> copied into each app's Docusaurus tree, NOT a separate npm package. Rationale:
> a publishable extractor + plugin package would add ~600 LOC of release plumbing
> (semantic-release, README, peer-dep matrix, Jest fixtures, CHANGELOG, version
> bumps in every consumer) for a 222-line script and a 30-line page — gold-plating
> per ADR-022 (apps-consume-or-abstractions). The script is copied verbatim into
> each adopting app's `scripts/` tree on adoption; the Docusaurus page reads
> `docs/features.json` directly via standard React + `import` (no plugin hook
> required because the file is already a static asset of the docs build).
> The OR-side pilot is sections 4 (Vue mount + route + menu entry + local
> manifest builder) and 5/6 (docs + tests). Sections 2 and 3 are kept in the
> tasks file as the rollout contract (copy-pattern, not package-install).

## 2. Build tooling — local manifest builder, copied per-app (no separate npm package)

> **RESCOPED 2026-06-12 (W33 honest-handoffs).** The original
> `@conduction/openspec-manifest` npm package was never published and would add
> ~600 LOC of release plumbing (semantic-release, README, peer-dep matrix, Jest
> fixtures, CHANGELOG, version bumps in every consumer) for a 222-line script.
> Per ADR-022 (apps-consume-or-abstractions) the canonical extractor is the
> in-tree `openregister/scripts/build-features-manifest.js`. Adopting apps
> **copy the script verbatim** into their own `scripts/` tree and wire the same
> `prebuild` + `manifest:check` npm scripts. `gray-matter` is the script's only
> non-stdlib dep and is already a transitive devDep of `webpack-vue-config`
> across the fleet, so no extra dep declaration is required.

- [x] 2.1 Canonical script lives at `openregister/scripts/build-features-manifest.js` (222 LOC). Implements spec discovery: prefer `./openspec/specs/*/spec.md`; fall back to `./specs/*/spec.md` when `./openspec/` is absent; warn-on-stderr when both are present; exit 0 with empty manifest when neither exists. Honours `--cwd` for testability. See the file header for the full contract documentation.
- [x] 2.2 Parser + extractor: uses `gray-matter` for YAML frontmatter; skips specs without frontmatter or missing `status:` (console-warn). Status filter: includes only `status ∈ {implemented, reviewed}` (skip others silently — expected exclusion). Extractor: first H1 after frontmatter → `title`; enclosing dir name → `slug`; first paragraph under the first `## Purpose` → `summary`; skip-and-warn when title or purpose is missing.
- [x] 2.3 docsUrl resolver: if frontmatter `docsUrl:` is set, validates via Node's `URL` constructor (rejects non-`https:` schemes or empty hostnames — stderr warn naming the spec, falls back to computed default); otherwise resolves git remote (`origin`) + default branch via `git symbolic-ref refs/remotes/origin/HEAD` (NOT the currently-checked-out branch) and builds `https://<host>/<owner>/<repo>/blob/<defaultBranch>/openspec/specs/<slug>/spec.md`. Supports both `github.com` AND `codeberg.org` remotes (the fleet migrated to Codeberg in 2026-05). Omits + warns when remote is unrecognised or default branch cannot be resolved.
- [x] 2.4 Writer + CLI: sorts entries alphabetically by title (locale-aware, case-insensitive); emits `docs/features.json` as pretty-printed JSON with shape `{schemaVersion: 1, generatedAt: "<ISO>", features: [...]}` and 2-space indent. Fails the build with non-zero exit + clear error when the emitted object doesn't satisfy the shape. The OR README + this tasks file document the `prebuild` integration, the `docs/features.json` committed-to-git location, and the recommended CI snippet `node scripts/build-features-manifest.js --check` for drift detection.
- [~] 2.5 Per-app adoption recipe (per-app rollout work, NOT this change): (a) copy `scripts/build-features-manifest.js` verbatim from openregister; (b) add `"prebuild": "node scripts/build-features-manifest.js"` and `"manifest:check": "node scripts/build-features-manifest.js --check"` to `package.json` scripts; (c) commit the generated `docs/features.json`; (d) add `npm run manifest:check` as a required CI step. The OR `manifest:check` exercises the contract end-to-end against a real spec corpus on every CI run — equivalent to the synthetic Jest suite originally scoped for the npm package.
