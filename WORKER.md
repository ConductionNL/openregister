RULES. PHPUnit 'Class "OCP\..." not found' at bootstrap: vendor/nextcloud/ocp has no autoload entry; add `-d auto_prepend_file=<a file that spl_autoload_registers OCP\ and NCU\ onto vendor/nextcloud/ocp/>` to the php command. `git config --global user.name "Ruben van der Linde"; git config --global user.email ruben@conduction.nl`. LOOP (state commands run in ~/q after `source bin/state.sh; source bin/work.sh`):

3. Work in a fresh ~/w/t-<n> per the type; delete it after (keep ~/w/vendor-* and ~/w/zips). Every ~90 min: `task_renew <id>; lease_renew $W 360`.

Never wait, poll, sleep, subscribe to PR events or schedule check-ins.

TYPES
verify (prs=n@sha,... in tree order): clone the app on origin/development; composer-cloud.sh; baseline unit suite (its failures are inherited). Per PR: `git fetch origin pull/<n>/head` (FETCH_HEAD != sha: skip), `git merge --no-ff --no-edit FETCH_HEAD` (conflict: abort, CONFLICT), `php -l` changed files (failure: undo, LINT). Unit suite on the tree; `npm ci && npm run test:unit` once if any PR touched JS/Vue. New failures: bisect by halves to the PR, RED with test names, rebuild without it (rerun a timing-sensitive test once first). Read each remaining diff. A PR whose commits are `feat(<app>): build <change>` implements openspec/changes/<change>: behaviour the change's specs ask for is expected, so judge it against those specs (GREEN unless it does something the change does not ask for, weakens an access check, or breaks a test). Otherwise: a behaviour change (return values, messages, removed access checks, deleted tests or assertions) is BLOCK; the rest GREEN. Record each at once, GREEN in tree order: `st_append queue/fleet-verdicts.tsv "<app>\t<n>\t<sha>\t<VERDICT>\t$W\t<tests run, baseline, new failures>"`. Do not merge: a local lane merges GREEN verdicts.
merge: never claimed by workers (local lane only).
fix (target=n; sha, verdict, branch, reason): check out the branch; head != sha: stale. CONFLICT: merge origin/development in, keep both sides' intent. RED: reproduce on the branch merged with development; red on plain development too = inherited, say so; else fix. BLOCK/LINT: fix what the reason names (sbom: bin/regen-sbom.sh; floors: restore the rating). Diff check: php -l, phpcs, phpstan, unit tests and eslint/vitest on touched files only. Green: commit, push to the branch, then `st_append queue/fleet-verdicts.tsv "<app>\t<n>\t<OLD sha>\tREVERIFY\t$W\t<what you did>; new head <sha>, verify it"`. Obsolete (already on development, code gone): close it with a neutral one-line comment. Cap 45 min.
cover (target=branch; lang, dirs, focus): unit tests for those dirs (`x/` recursive, `x/*.php` or `x/*` only files directly in x). Change only test files (and test config for a new test dir). lang=js: vitest/jest specs where the app keeps them, run its unit script, same rules below (mock only HTTP, stores and Nextcloud globals). Baseline the suite. Take classes with most logic and no tests (focus=untested) or thin tests (thin). Assert real behaviour (return values, exceptions, exact collaborator calls); mock only boundaries (mappers, IDBConnection, HTTP clients, IUserSession, IConfig, IL10N, LoggerInterface). No assertion-free, getter-only or skipped tests. Per new test file break one subject line, see a test fail, `git checkout -- lib/`. Coverage metadata is strict: @covers/#[CoversClass] for the subject and @uses/#[UsesClass] for every other real lib/ class executed, or the test is risky and its coverage dropped. Match existing tests' namespace, base class, SPDX header. Batches of ~8 classes, at most 2 PRs per task: no failures beyond baseline, php -l, commit `test(<app>): cover <area>`, push `<target>-<k>`, `gh api repos/ConductionNL/<app>/pulls -f title=... -f head=... -f base=<base> -f body=...` (classes, test count, suite before/after, "Tests only; no production code changed.").
review (openregister, target=n; sha, last_approved, title): read-only on GitHub. Blobless clone, fetch main and pull/<n>/head; head != sha: stale. Read the body once. Diff vs origin/main (and vs last_approved; judge it all). Each changed body vs old: conditions, order, early returns, exceptions and messages, HTTP codes, defaults, nulls, key order. Access checks still run first, same allowed and refused outcomes, no fail-open on exception, null or missing config, non-arrays still refused where an array was required; audit, route attributes, listener order, event/occ/MCP names unchanged; code moved into a strict_types file from a non-strict one risks TypeErrors; new interfaces bind the same class; no clock- or timezone-pinned tests. phpstan on changed lib files; on the PR merged with origin/main (`git merge --no-commit --no-ff origin/main`, then abort) run tests/Unit/Architecture, Service/Rules, Controller, Contract (+ Service/Rbac for access code) and touched classes' tests; eslint/jest for touched frontend. Known reds: DbalConnectionFactoryBehaviourTest, MappingSlugFallbacksTest::testAMissingTransliteratorKeepsTheName, clock-bound JwtValidatorBehaviourTest. Broken fleet callers: no block, list `FLEET: <app> <file:line> <method>`. A PR with commits `feat(openregister): build <change>` implements openspec/changes/<change>: behaviour that change's specs ask for is expected, not a defect. BLOCK only for a confirmed openregister defect (behaviour change, access weakening, broken in-repo caller, failing test); a conflict is no block. Unfinished: no verdict. Record `st_append verdicts.txt "<n> <full sha> APPROVE|BLOCK <neutral reason, under 300 chars>"`.
review on a fleet app (base development; sha, branch, title): the same behaviour checks against origin/development, then the app's unit suite and the touched classes' tests on the PR merged with development; record `st_append queue/fleet-verdicts.tsv "<app>\t<n>\t<sha>\t<GREEN|BLOCK|RED>\t$W:review\t<reason>"`. Never merge.
measure (target=queue/coverage/<app>.json): measure, commit nothing to the app. Clone on base, composer-cloud.sh. PHP: `pecl install pcov` or `apt-get install -y php8.3-pcov` (enable it), then `php -d memory_limit=2G -d pcov.enabled=1 -d pcov.directory=lib vendor/bin/phpunit -c <unit config> --coverage-clover /tmp/c.xml`; no pcov/xdebug: skip PHP. Without `pcov.directory=lib` pcov instruments `src/` (Vue) instead and PHP reads 0-33%. JS: `npm ci`, then `npx vitest run --coverage --coverage.reporter=json-summary` (jest: `--coverage --coverageReporters=json-summary`) into coverage/coverage-summary.json. From ~/q: `python3 bin/coverage_dirs.py --app <app> --commit <sha> [--clover /tmp/c.xml] [--js <app>/coverage/coverage-summary.json] [--php-tool none] > /tmp/m.json && st_put queue/coverage/<app>.json /tmp/m.json`. Result: the php/js pct.
gap (target=row; criterion, row, fix): do what fix says, for this app only. Fleet: branch quality/gap-<row>-<word>, diff check green, PR to development (merged after verify). openregister: PR to main. "Merge the open PR #n": verify it as a one-PR tree and record the verdict (a local lane merges it). Already done: result `already done`.
build (target=<change>; change, open): build an openspec change of an app. Fleet app: base development. openregister: base main, branch build/<change> instead of quality/build-<change>, PR to main, a row in scripts/component-map.csv for every new lib file; review and the integrator lane land it, never merge it yourself. Clone the app on its base; `git ls-remote origin "refs/heads/quality/build-<change>*"` non-empty, or `git log origin/development -5 --format=%s -- openspec/changes/<change>` shows a build after the task's created time: result `already building`. Read the change completely (proposal.md, design.md, specs/, tasks.md) and the app's existing code and conventions first. Implement every unchecked task that can be done in code and unit tests; leave live, browser, e2e, screenshot, measurement and release tasks unchecked (say so in the PR). Rules: procedures (Woo, bezwaar, VTH, ...) are case types, flows and configuration, and code is generic, named by what it does, never by a procedure; pages are manifest configuration over the shared @conduction/nextcloud-vue widgets, not hand-built pages; no /settings/user/<app> pages (user settings go in the app's settings modal, app settings in admin); data lives in OpenRegister objects through its APIs, no own tables; CSS variables only, WCAG AA; every new PHP class gets unit tests with real assertions; SPDX headers; @spec openspec/changes/<change> tags on new methods. Tick the tasks you did in tasks.md. Diff check: php -l, phpcs, phpstan, unit tests of touched classes, eslint on touched JS/Vue, and the app's whole unit suite once with no failures beyond its baseline. Branch quality/build-<change>, commits `feat(<app>): build <change> [skip ci]`, PR to development (title `feat(<app>): build <change>`, body: tasks done, tasks left and why, tests added, suite before/after). Build the WHOLE change in this one task: after each finished task commit and push (so nothing is lost if the session ends), open the PR after the first green task, then keep building until every code task is ticked. Do not stop at a time mark; stop early only when your context is nearly full, and then result `partial` with what is left. A missing piece in openregister that the change needs: build it there too as its own PR (base main, branch build/<change>), do not leave the change waiting for it. A local lane merges after verify; never merge. A continuation row (id ending :c2..:c4; payload cont, prev, left) resumes an earlier partial or blocked build: build the unchecked code tasks in tasks.md, starting from the existing PR/branch if one is open (push to it; the already-building check does not apply), else from the base.

If any command is refused by a permission check, do not retry or work around it: mark that task `failed: permission`, then CONTINUE with the next task (do not stop the session for it).

FINAL MESSAGE (under 12 lines): tasks per type and result, PRs opened, merged, failed.
