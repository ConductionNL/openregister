TYPES
verify (prs=n@sha,... in tree order): clone the app on origin/development; composer-cloud.sh; baseline unit suite (its failures are inherited). Per PR: `git fetch origin pull/<n>/head` (FETCH_HEAD != sha: skip), `git merge --no-ff --no-edit FETCH_HEAD` (conflict: abort; then `git merge-tree --write-tree origin/development FETCH_HEAD`: when it merges clean on development alone the conflict is only with an earlier PR of the tree, record REVERIFY with reason "conflicts only with an earlier PR of the verify tree" so it is verified alone later; else CONFLICT), `php -l` changed files (failure: undo, LINT). Unit suite on the tree; `npm ci && npm run test:unit` once if any PR touched JS/Vue. New failures: bisect by halves to the PR, RED with test names, rebuild without it (rerun a timing-sensitive test once first). Read each remaining diff. A PR whose commits are `feat(<app>): build <change>` implements openspec/changes/<change>: behaviour the change's specs ask for is expected, so judge it against those specs (GREEN unless it does something the change does not ask for, weakens an access check, or breaks a test). Otherwise: a behaviour change (return values, messages, removed access checks, deleted tests or assertions) is BLOCK; the rest GREEN. Record each at once, GREEN in tree order: `st_append queue/fleet-verdicts.tsv "<app>\t<n>\t<sha>\t<VERDICT>\t$W\t<tests run, baseline, new failures>"`. Do not merge in a verify task: GREEN verdicts become merge tasks.
merge (fleet app, base development; prs=n@sha,... in tree order; the claim gave you leases/merge-<app>.lease): K=~/w/t-<k>; from ~/q, each step one foreground call: `bash bin/cm_tree.sh prep <app> $K`, `bash bin/cm_tree.sh base <app> $K`, `bash bin/cm_tree.sh build <app> $K <prs>`, `bash bin/cm_tree.sh tree <app> $K`; when the tree adds failures, `bash bin/cm_tree.sh cull <app> $K` (exit 0 = the rebuilt tree adds none; exit 1: `task_done <id> "failed: <its line>"`). A step that exits 2 or prints TIMEOUT: task failed, nothing lands. Then review every IN PR of $K/logs/<app>.tree per briefs/CLOUD-REVIEW.md (decided modes, no questions, the whole diff against origin/development) and record each with `bash bin/cm_land.sh review <app> <n> <full sha> APPROVE|REQUEST_CHANGES $W "<mode>; <blockers>; <concerns>"`. Then `merge_lock_renew <app>` (1 = lost: land nothing, `task_done <id> "failed: merge lock lost"`), then `bash bin/cm_land.sh land <app> $K $W`: it merges each IN PR with an APPROVE at its head, merge gate first, pinned to the sha, records MERGED/RED/FAIL in queue/fleet-merged.tsv, and writes verdicts for the PRs left out (CONFLICT, LINT, RED; MOVED as REVERIFY) so fix and verify tasks follow. Pass its last line to `task_done <id> "<line>"`, which also releases the merge lock; never end the session between land and task_done. Never re-merge a FAIL row by hand.
fix (target=n; sha, verdict, branch, reason): check out the branch; head != sha: stale. CONFLICT: merge origin/development in, keep both sides' intent. RED: reproduce on the branch merged with development; red on plain development too = inherited, say so; else fix. BLOCK/LINT: fix what the reason names (sbom: bin/regen-sbom.sh; floors: restore the rating). Diff check: php -l, phpcs, phpstan, unit tests and eslint/vitest on touched files only. Green: commit, push to the branch. END TO END (fleet app, base development, never openregister): you may then take the PR to merged in the same task: `merge_lock <app>` (1 = another merger holds it: skip to the REVERIFY row), run the merge steps above as a one-PR tree `prs=<n>@<new head>`, review it per briefs/CLOUD-REVIEW.md over its whole diff including your own commits and record the review with cm_land.sh review (REQUEST_CHANGES: fix the blockers, push, review the new head once more; still blocked: leave it, the BLOCK verdict stands), then `bash bin/cm_land.sh land`, then `merge_unlock <app>` (task_done of a fix task does not release it). Result `merged #<n> at <sha>` when it landed. When it did not land, or you skip the end-to-end step: `st_append queue/fleet-verdicts.tsv "<app>\t<n>\t<OLD sha>\tREVERIFY\t$W\t<what you did>; new head <sha>, verify it"`.
