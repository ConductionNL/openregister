description: Check the translation catalogues and one locale
argument-hint: "[locale, e.g. nl]"
---
Read the l10n rules in `CLAUDE.md` before changing anything in `l10n/`. `l10n/*.js` is never edited by hand; `npm run l10n:apply` is the only writer.

Run from the repository root:

```bash
npm run test:l10n          # every t()/n() call in src/ has a key in l10n/en.js
npm run test:l10n:parity   # every locale complete and well-formed
npm run check:l10n         # missing, unused and unwrapped strings
```

With a locale in $ARGUMENTS, also run:

```bash
npm run l10n:status -- $ARGUMENTS
npm run l10n:selfcheck -- $ARGUMENTS
```

Report what is red and why. `test:l10n` being red on keys that a merge added is a known state described in `CLAUDE.md`; say so rather than working around it.
